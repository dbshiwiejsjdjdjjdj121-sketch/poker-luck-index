# Initial guide release — 2026-09-07 (Asia/Shanghai)

## Scope and sourcing

Replaced the earlier poker tools with an English public festival guide. The owner's revised scope is one overview per festival/championship, with representative buy-ins, travel essentials and official entry points. Full schedule replication and individual event pages are excluded.

The seed contains 20 distinct real overviews: 10 WSOP Circuit stops, WSOP Paradise, five WPT/Prime championships, EPT Prague, PokerStars Open Aix-en-Provence and two APT series. Dates range from the currently running September circuit through December 2026. Official calendar/event HTML was read on September 6 UTC / September 7 China time; exact successful-read timestamps and URLs are stored with the data. No fictitious entries were added to reach the target. WPT championship-only dates are explicitly labelled.

Representative entry fees, multiple starting flights, starting chips, levels and re-entry rules are included only where confirmed. Council Bluffs has a published-date discrepancy and retains an explicit review note. The Venetian promotion page had an apparently old offer code, which is not advertised as valid. Unknown local tax rules, travel options and prices remain unconfirmed. Eight city guides have sufficient specific content for indexing; all city pages remain available to visitors.

The link check covered 74 unique source/official URLs. Six returned bot blocking and one tax portal timed out; no confirmed HTTP 404 was found. Hilton property pages were separately verified through browsing. A failure does not reset verification dates or remove a festival.

## Validation completed before release

- 16 data/auth tests: interval overlap, venue dates through a DST transition, cancellations, currency isolation, unknown money, duplicate identities, malformed data, stale checks, quarantine with valid updates preserved, failed-source baseline preservation, safe JSON-LD and OTP state transitions.
- Lint, production build and TypeScript check passed with Next.js 16.3.4.
- Local HTTP smoke: 67 public/retired routes, English metadata, canonical links, festival Event JSON-LD, sitemap membership, noindex filters/account, 404s, invalid email/code input.
- Protected Vercel preview passed the same smoke check with noindex and disallowed robots.
- Browser: desktop homepage; 390px phone homepage, calendar and EPT Prague overview; currency + buy-in selection, empty results, URL restoration, travel and official bottom links; no horizontal overflow.
- Email integration used a local SMTP receiver and a unique temporary Firebase test account. Browser verified successful code delivery to the local receiver, resend countdown, incorrect code, successful sign-in, session recovery on navigation/reload and sign-out. No message was sent to a real email address. Expiry, retry cap and one-time consumption are covered by tests. Existing production Resend/SMTP configuration is retained; live inbox delivery via Resend was not tested.

## Migration and operational notes

Old daily/weekly Codex SEO automations remain paused. The legacy GitHub SEO workflows were disabled; the source workflow is removed. GitHub’s existing OAuth token cannot add a new workflow (missing workflow scope), so validation runs locally inside the mandatory release gate; no replacement GitHub workflow was added. Vercel Git auto-deploy is disabled so production publishes use the staged deployment and smoke-check gate.

Old code is preserved in Git history. The original uncommitted workflow and strategy edits were stashed as “Preserve user SEO changes before ALL IN Poker Guide rebuild”; they were not mixed into this release. Existing Firebase users/history were not erased.

Runtime high/critical audit findings were addressed by updating Next.js, Nodemailer and compatible transitive dependencies. Remaining Firebase transitive UUID findings concern unused buffer-writing APIs; review future upstream updates during product maintenance, outside the data-only daily task. The production site uses no analytics scripts or paid data APIs.

Production URLs, release state and the live rollback rehearsal are recorded after promotion. Daily scheduling is enabled only after the first production release and maintenance rehearsal succeed.
